איך קובעים סיבוכיות זמן ריצה

סיבוכיות זמן הריצה מתארת איך מספר הצעדים שהקוד מבצע גדל כאשר הקלט גדל. לא סופרים שניות וגם לא את המספר המדויק של הצעדים. מחפשים את קצב הגידול (נקרא גם סדר הגודל) ורושמים אותו בסימון O. את הסיבוכיות קובעים בארבעה שלבים:

  1. מגדירים את גודל הקלט. בוחרים אות וכותבים מה היא מייצגת, לדוגמה: "נסמן ב־n את מספר החוליות בשרשרת". כשיש שני קלטים בוחרים שתי אותיות, n ו־m.
  2. סופרים כמה פעמים מתבצעת כל לולאה במקרה הגרוע. המקרה הגרוע הוא הקלט שבו הקוד מבצע הכי הרבה צעדים. לדוגמה: בחיפוש זה קלט שבו הערך אינו נמצא.
  3. מחברים או מכפילים. כשלולאות באות זו אחר זו מחברים את מספרי הסיבובים שלהן. כשלולאה נמצאת בתוך לולאה מכפילים אותם. זימון של פעולה אינו נחשב צעד אחד. סופרים אותו לפי מספר הצעדים שהפעולה המזומנת מבצעת.
  4. מפשטים. מוחקים מספרים קבועים (גם כאלה שמכפילים את n) ומשאירים את המחובר שגדל הכי מהר. לדוגמה: 3n + 5 הוא O(n) ו־n² + n הוא O(n²).

אלה סדרי הגודל הנפוצים, מהיעיל ביותר (משמאל) עד היעיל פחות (מימין):

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ)

לולאה פנימית שתלויה בחיצונית

for (int i = 0; i < n - 1; i++)
    for (int j = i + 1; j < n; j++)
        if (a[i] == a[j])
            count++;

בסיבוב הראשון של הלולאה החיצונית, הלולאה הפנימית מתבצעת n-1 פעמים. בסיבוב השני n-2 פעמים וכך הלאה עד 1. הסכום הוא n(n-1)/2, בערך חצי מ־n². לכן הסיבוכיות היא O(n²). הלולאה הפנימית מתקצרת מסיבוב לסיבוב, אבל סדר הגודל נשאר n².

לולאה בתוך לולאה שאינה O(n²)

int i = 0;
while (i < n)
{
    int j = i;
    while (j < n && a[j] == a[i])
        j++;
    count++;
    i = j;
}

הקוד סופר במשתנה count את הרצפים של ערכים שווים במערך a שאורכו n. הלולאה הפנימית מקדמת את j עד סוף הרצף שמתחיל בתא i. אחריה i מקבל את הערך של j ולכן הלולאה הפנימית אינה עוברת פעמיים על אותו תא. בכל הסיבובים של הלולאה החיצונית יחד j מתקדם n פעמים ולכן הסיבוכיות היא O(n) ולא O(n²). לפני שמכפילים, בודקים כמה פעמים הלולאה הפנימית מתבצעת בסך הכול.

זימון של פעולה בתוך לולאה

Node<int> p = lst;
while (p != null)
{
    if (Exists(p.GetNext(), p.GetValue()))
        return true;
    p = p.GetNext();
}
return false;

בקוד נראית לולאה אחת, אבל הפעולה Exists מחפשת את הערך בהמשך השרשרת ולכן עוברת בעצמה על החוליות. יש n סיבובים (n הוא מספר החוליות). בכל סיבוב Exists עוברת על עד n חוליות ולכן הסיבוכיות היא O(n²).

זימון של פעולת עזר פעם אחת או פעמיים מחוץ ללולאה אינו מעלה את סדר הגודל: O(n) + O(n) הוא O(n).

מעבר על תור והחזרת האיברים

public static int Count(Queue<int> q, int x)
{
    Queue<int> temp = new Queue<int>();
    int count = 0;
    while (!q.IsEmpty())           // n
    {
        if (q.Head() == x) count++;
        temp.Insert(q.Remove());
    }
    while (!temp.IsEmpty())        // n
        q.Insert(temp.Remove());
    return count;
}

שתי הלולאות באות זו אחר זו ולכן מחברים: n + n. הסיבוכיות היא O(n). היא עולה ל־O(n²) רק כאשר כל המעבר הזה, כולל ההחזרה, נמצא בתוך לולאה נוספת שמתבצעת עד n פעמים.

איך מגדירים את n ומהו המקרה הגרוע

מה מייצגת האות n

  • בשרשרת חוליות: מספר החוליות.
  • בתור: מספר האיברים.
  • בעץ בינארי: מספר הצמתים.
  • במערך או במחרוזת: האורך. במערך דו־ממדי מסמנים ב־n את מספר השורות וב־m את מספר העמודות. מעבר על כל התאים הוא O(n·m).
  • במספר שלם: הערך שלו או מספר הספרות שלו. כותבים במפורש באיזה מהשניים בחרתם.

אם השאלה כבר הגדירה אות ("n הוא מספר המתחרים באוסף"), משתמשים באות של השאלה ובהגדרה שלה.

המקרה הגרוע

כשמספר הצעדים תלוי בערכים שבקלט ולא רק בגודלו, קובעים את הסיבוכיות לפי הקלט שבו הקוד מבצע הכי הרבה צעדים וכותבים "במקרה הגרוע".

  • חיפוש: הערך אינו נמצא או נמצא במקום האחרון שנבדק.
  • הכנסה לשרשרת ממוינת: הערך גדול מכל הערכים.
  • מחיקת כפילויות: כל הערכים שונים זה מזה ולכן דבר אינו נמחק והמבנה אינו מתקצר.
  • ירידה מהשורש שממשיכה בכל צומת רק לבן אחד: לכל צומת יש בן יחיד ולכן המסלול עובר בכל הצמתים.

פקודת return בתוך לולאה מקצרת את הריצה רק בחלק מהקלטים. היא אינה משנה את הסיבוכיות במקרה הגרוע.

איך מנסחים תשובה על סיבוכיות

בשאלון כתוב "נמקו את תשובתכם". תשובה שיש בה רק O(n) אינה מנומקת. בתשובה כותבים שלושה דברים:

  1. מה מייצגת האות n.
  2. כמה פעמים מתבצעת כל לולאה (או כמה קריאות רקורסיביות יש) ומה נעשה בכל סיבוב.
  3. התוצאה, עם המילים "במקרה הגרוע" כשהיא תלויה בערכים שבקלט.

לדוגמה: "נסמן ב־n את מספר האיברים בתור. הלולאה החיצונית מתבצעת עד n פעמים. בכל סיבוב שלה הלולאה הפנימית עוברת על כל האיברים שנשארו בתור, כלומר על n איברים לכל היותר. לכן סיבוכיות זמן הריצה במקרה הגרוע היא O(n²)."

פעולות על שרשרת חוליות, תור ועץ בינארי

כל פעולות הממשק של חוליה, של תור ושל חוליה בינארית מתבצעות ב־O(1). כך גם גישה לתא במערך. הסיבוכיות של הקוד שלכם נקבעת לפי מספר הפעמים שהוא מזמן אותן.

פתרון יעיל והשוואה בין שני פתרונות

איך קובעים איזה משני הפתרונות יעיל יותר. קובעים את הסיבוכיות של כל פתרון לפי אותה הגדרה של n. הפתרון שסדר הגודל שלו נמוך יותר הוא היעיל יותר. בתשובה כותבים את הסיבוכיות של כל פתרון ואת המסקנה, לדוגמה: "הפעולה הראשונה יעילה יותר, כי סיבוכיות זמן הריצה שלה היא O(n) ושל הפעולה השנייה היא O(n²)".

כשנדרש פתרון ב־O(n)

בקוד שלכם לא תהיה לולאה שעוברת על כל הקלט בכל סיבוב של לולאה אחרת. אסור גם לזמן בתוך לולאה פעולה שעוברת על הקלט. הדרכים המקובלות להימנע מכך:

  • עוברים על הקלט פעם אחת עם משתני עזר (מונה, סכום, מקסימום) ולא עוברים עליו שוב לכל איבר.
  • את הערכים שאינם משתנים (אורך השרשרת, סכום כולל) מחשבים פעם אחת לפני הלולאה.
  • כשהקלט ממוין משתמשים בשתי הפניות שרק מתקדמות, כמו בדוגמה שמשמאל.
  • כשהערכים הם מספרים שלמים בין 0 ל־k משתמשים במערך מונים שבו התא c[v] סופר כמה פעמים הופיע הערך v. מעבר על הקלט ועל המונים הוא O(n + k).

שתי הפניות על שתי שרשראות ממוינות. הלולאה סופרת במשתנה count את הערכים שמופיעים גם בשרשרת a וגם בשרשרת b. בכל שרשרת הערכים מסודרים בסדר עולה ושונים זה מזה.

while (a != null && b != null)
{
    if (a.GetValue() < b.GetValue())
        a = a.GetNext();
    else if (a.GetValue() > b.GetValue())
        b = b.GetNext();
    else
    {
        count++;
        a = a.GetNext();
        b = b.GetNext();
    }
}

בכל סיבוב לפחות אחת מההפניות מתקדמת ואף אחת אינה חוזרת אחורה. לכן יש לכל היותר n + m סיבובים והסיבוכיות היא O(n + m), כאשר n ו־m הם מספרי החוליות בשתי השרשראות. פתרון שמחפש כל ערך של a מתחילת b הוא O(n·m).

מה חוזר בשאלות הסיבוכיות בבגרות

בבחינת הבגרות כמעט אין שאלה שלמה על סיבוכיות. שואלים עליה בסעיף קצר בסוף שאלה על שרשרת, על תור, על עץ או על מערך, בנוסח קבוע: "מהי סיבוכיות זמן הריצה של הפעולה? נמקו את תשובתכם". הסעיף מופיע בארבע צורות:

  • סיבוכיות של פעולה שכתבתם בסעיף הקודם. זו הצורה הנפוצה ביותר. התשובה תלויה בקוד שלכם.
  • סיבוכיות של קוד נתון, אחרי סעיף מעקב ואחרי הסעיף "מה עושה הפעולה". יש שאלות שבהן נתונות שתי פעולות והשנייה מזמנת את הראשונה. בשאלה אופיינית כזאת הסיבוכיות של הראשונה היא O(n) ושל השנייה O(n²).
  • דרישת סיבוכיות שכתובה בשאלה. לדוגמה: "הפעולה חייבת לעבוד בסיבוכיות זמן ריצה של O(N)".
  • השוואה בין שתי פעולות נתונות שעושות אותו דבר: "מי מבין שתי הפעולות יעילה יותר?".

התשובה היא בדרך כלל O(n) או O(n²) ולעיתים O(n·m), O(n + k) או O(n³). תשובה עם log אינה אופיינית לסעיפים האלה.

פעולה שמזמנת פעולה אחרת

כאן טועים הכי הרבה: סופרים את הזימון כצעד אחד. בפעולה רואים לולאה אחת או קריאה רקורסיבית אחת, אבל בכל סיבוב או בכל קריאה הפעולה מזמנת פעולה אחרת שעוברת בעצמה על הקלט.

  • כשפעולה מזמנת לכל חוליה פעולת עזר שהיא O(n), הסיבוכיות של הפעולה המזמנת היא O(n²).
  • כך גם ברקורסיה. לדוגמה: פעולה רקורסיבית בודקת אם יש במערך באורך n שני ערכים שסכומם נתון. היא מבצעת עד n קריאות רקורסיביות ובכל קריאה מזמנת פעולת עזר שמחפשת ערך במערך. לכן הסיבוכיות שלה היא O(n²).
  • יש שאלות שבהן כתוב מהי הסיבוכיות של פעולת עזר נתונה, לדוגמה O(n). משתמשים בנתון הזה כשמנמקים את הסיבוכיות של הפעולה שכתבתם.

תור: החזרת האיברים ולולאה חיצונית

זימון חוזר של פעולה שעוברת על התור. לדוגמה: פעולת עזר מקבלת תור ומספר z ובודקת אם יש בתור רצף של z ערכים שווים. היא עוברת על התור פעם אחת ולכן היא O(n). פעולה רקורסיבית מקבלת את התור ואת מספר האיברים שבו. בכל קריאה היא מזמנת את פעולת העזר ומקטינה את המספר ב־1, עד שפעולת העזר מחזירה true. התור אינו מתקצר ויש עד n קריאות. לכן הסיבוכיות היא O(n²) במקרה הגרוע.

לכל איבר עוברים על שאר התור. לדוגמה: פעולה שמאחדת את ההזמנות של אותו לקוח ומשתמשת רק בתורים. בכל סיבוב מוציאים הזמנה, עוברים על כל שאר התור ומחזירים אליו את ההזמנות של הלקוחות האחרים. במקרה הגרוע כל הזמנה שייכת ללקוח אחר ויש n סיבובים. לכן התשובה היא O(n²). כשפעולה אחרת מזמנת את הפעולה הזאת פעם אחת ואחר כך עוברת פעם אחת על התור המאוחד, הסיבוכיות אינה עולה: O(n²) + O(n) הוא O(n²).

כשגודל הקלט אינו רק n

  • שני קלטים. כשעוברים על העץ השני לכל צומת בעץ הראשון, הסיבוכיות היא O(n·m), כאשר n ו־m הם מספרי הצמתים בשני העצים. התשובה O(n²) נכונה רק אם הגדרתם את n כמספר הצמתים בעץ הגדול מבין השניים.
  • פרמטר מספרי נוסף. כשלולאה אחת עוברת על מערך באורך n ואחריה לולאה אחרת עוברת על מערך מונים באורך k, הסיבוכיות היא O(n + k) ולא O(n·k).
  • ערך ששמור בחוליה. לדוגמה: בכל חוליה שמורים ערך ומספר המופעים שלו. כדי להכניס ערך עוברים על החוליות ולכן n הוא מספר החוליות ולא מספר המופעים.
  • אות שהשאלה הגדירה. לדוגמה: N הוא אורך השרשרת הארוכה מבין השתיים והפעולה נדרשת לעבוד ב־O(N). מעבר אחד על שתיהן הוא עד 2N צעדים ולכן עומד בדרישה.

מעברים זה אחר זה, יציאה מוקדמת ושני אינדקסים

  • שני מעברים זה אחר זה. לדוגמה: סופרים את החוליות במעבר אחד ומטפלים בהן במעבר נוסף. התשובה היא O(n) ולא O(n²).
  • יציאה מוקדמת. לדוגמה: שלוש לולאות זו בתוך זו מחפשות שלושה איברים שסכומם נתון. הן מסתיימות כשהאיברים נמצאו, אבל במקרה הגרוע הלולאות מגיעות אליהם רק בסוף או שאין איברים כאלה. לכן הסיבוכיות היא O(n³). כך גם בחיפוש רקורסיבי בשרשרת: התשובה היא O(n), לפי המקרה שבו הערך אינו נמצא.
  • שני אינדקסים בלולאה אחת. לדוגמה: נתונות שתי פעולות על מערך ממוין. הראשונה בודקת כל זוג תאים במערך והיא O(n²). השנייה מקדמת אינדקס אחד מכל קצה של המערך עד שהאינדקסים נפגשים. היא O(n) ולכן יעילה יותר.

טעויות נפוצות

ברשימה הזאת כל שורה היא טעות של תלמידים. אין לפעול לפיה.

בחישוב

  • מכפילים לולאות שבאות זו אחר זו או מחברים לולאות שנמצאות זו בתוך זו.
  • סופרים זימון של פעולה כצעד אחד, בלי לבדוק אם הפעולה המזומנת עוברת על הקלט.
  • קובעים O(n²) רק מפני שיש לולאה בתוך לולאה, בלי לבדוק כמה פעמים הלולאה הפנימית מתבצעת בסך הכול.
  • קובעים את התשובה לפי קלט שבו יש יציאה מוקדמת ולא לפי המקרה הגרוע.
  • מניחים שכל פעולה רקורסיבית היא O(2ⁿ). פעולה עם קריאה רקורסיבית אחת על המשך השרשרת היא O(n).

בניסוח

  • כותבים את התשובה בלי להגדיר מה מייצגת האות n או משתמשים באות n לשני קלטים שונים.
  • משאירים קבועים בתשובה: O(2n) או O(n²/2). התשובות המפושטות הן O(n) ו־O(n²).
  • כותבים רק את התוצאה, בלי המשפט שמסביר כמה פעמים מתבצעת כל לולאה.
  • מנמקים את הסיבוכיות של פתרון אחר ולא של הקוד שכתבתם בסעיף הקודם.
  • שוכחים את המילים "במקרה הגרוע" כשמספר הצעדים תלוי בערכים שבקלט.
