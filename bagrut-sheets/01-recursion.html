איך כותבים פעולה רקורסיבית

לפני שכותבים שורת קוד אחת, עונים בכתב על שלוש שאלות. אחרי שעונים על שלושתן נשאר בעיקר לתרגם את התשובות לקוד.

  1. תנאי העצירה. מהו הקלט הקטן ביותר שעבורו התשובה ידועה בלי חישוב? לדוגמה: שרשרת ריקה, עץ ריק, המספר 0.
  2. הקריאה הרקורסיבית. על איזה קלט קטן יותר קוראים לפעולה? הקלט חייב להתקרב לתנאי העצירה בכל קריאה, אחרת הפעולה לא תסתיים.
  3. שילוב התוצאה. מניחים שהקריאה הרקורסיבית החזירה תשובה נכונה עבור הקלט הקטן יותר. מה נשאר לעשות בקריאה הנוכחית כדי לקבל את התשובה לקלט כולו?

דוגמה: סכום הערכים בשרשרת חוליות. הצבעים מסמנים את התשובות לשלוש השאלות.

public static int Sum(Node<int> p)
{
    if (p == null)
        return 0;
    int rest = Sum(p.GetNext());
    return p.GetValue() + rest;
}

בשלב השילוב לא בודקים איך הקריאה חישבה את rest. סומכים על התוצאה שלה ומטפלים רק בחוליה הנוכחית.

תבניות הרקורסיה שכדאי לזהות

רוב הפעולות הרקורסיביות בבגרות כתובות לפי אחת מהתבניות הבאות או לפי שילוב של שתיים מהן. כשמזהים את התבנית קל יותר לכתוב את הפעולה או לעקוב אחריה.

1. פעולה שמחזירה ערך ומחשבת אותו בדרך חזרה

כך כותבים ספירה, סכום ומקסימום. החישוב נעשה אחרי שהקריאה הרקורסיבית חזרה.

// כמה חוליות בשרשרת ערכן זוגי
public static int CountEven(Node<int> p)
{
    if (p == null) return 0;
    int rest = CountEven(p.GetNext());
    if (p.GetValue() % 2 == 0)
        return rest + 1;
    return rest;
}

2. בדיקה שמחזירה אמת או שקר

פעולה שבודקת אם קיים איבר מתאים מחזירה false עבור קלט ריק ומחברת את תוצאות הקריאות ב־||. פעולה שבודקת אם כל האיברים מתאימים מחזירה true עבור קלט ריק ומחברת אותן ב־&&.

// האם הערך x נמצא בעץ
public static bool Exists(BinNode<int> t, int x)
{
    if (t == null) return false;
    if (t.GetValue() == x) return true;
    return Exists(t.GetLeft(), x)
        || Exists(t.GetRight(), x);
}

3. הוראות לפני הקריאה הרקורסיבית או אחריה

מה שכתוב לפני הקריאה מתבצע מתחילת השרשרת לסופה. מה שכתוב אחריה מתבצע בדרך חזרה, כלומר מסוף השרשרת לתחילתה. ההערה שליד כל הדפסה מראה מה היא מדפיסה עבור השרשרת 1 → 2 → 3. הפלט המלא הוא 1 2 3 3 2 1.

// מדפיסה את הערכים לפי הסדר ואחר כך בסדר הפוך
public static void Print(Node<int> p)
{
    if (p == null) return;
    Console.Write(p.GetValue());  // 1 2 3
    Print(p.GetNext());
    Console.Write(p.GetValue());  // 3 2 1
}

4. שתי קריאות רקורסיביות

התבנית אופיינית לעצים. קוראים לפעולה על תת־העץ השמאלי ועל הימני ומשלבים את שתי התוצאות, לעיתים גם עם ערך השורש.

// גובה העץ
public static int Height(BinNode<int> t)
{
    if (t == null) return -1;
    int left = Height(t.GetLeft());
    int right = Height(t.GetRight());
    return 1 + Math.Max(left, right);
}

5. פעולה שמחזירה חוליה ומחברת את השרשרת מחדש

הפעולה מחזירה את החוליה הראשונה של השרשרת אחרי השינוי. בכל קריאה מחברים לחוליה הנוכחית את מה שחזר מהקריאה על המשך השרשרת.

// מוחקת מהשרשרת את כל החוליות שערכן x
public static Node<int> Delete(Node<int> p,
                               int x)
{
    if (p == null) return null;
    Node<int> rest = Delete(p.GetNext(), x);
    if (p.GetValue() == x)
        return rest;      // מדלגים על החוליה
    p.SetNext(rest);
    return p;
}

6. פרמטר שמעביר מידע לקריאות הבאות

כשהחישוב תלוי במה שהיה לפני האיבר הנוכחי, מוסיפים פרמטר שבו מעבירים את המידע הזה. לעיתים צריך לכתוב פעולה נוספת שרק מזמנת את הפעולה הרקורסיבית עם ערך התחלתי לפרמטר.

// בכמה צמתים הערך גדול מכל הערכים שבמסלול מהשורש אליהם
public static int Count(BinNode<int> t, int max)
{
    if (t == null) return 0;
    int c = 0;
    if (t.GetValue() > max)
    { c = 1; max = t.GetValue(); }
    return c + Count(t.GetLeft(), max)
             + Count(t.GetRight(), max);
}

אותן תבניות מופיעות גם בפעולות על מספר ועל מערך. במקרים האלה אין מבנה נתונים שקטן מקריאה לקריאה ולכן פרמטר מספרי הוא שמתקרב לתנאי העצירה.

רקורסיה על הספרות של מספר

בכל קריאה מטפלים בספרת האחדות n % 10 וקוראים לפעולה על n / 10, שהוא המספר בלי ספרת האחדות. הספרות נבדקות מימין לשמאל.

// כמה פעמים הספרה d מופיעה במספר n
public static int CountDigit(int n, int d)
{
    int c = 0;
    if (n % 10 == d) c = 1;
    if (n < 10) return c;
    return c + CountDigit(n / 10, d);
}

ביטוי כמו G(n / 10) * 10 + n % 10, שבו G היא הפעולה הרקורסיבית עצמה, בונה מספר חדש: הוא מצמיד את ספרת האחדות מימין לתוצאה שחזרה מהקריאה.

רקורסיה על מערך בעזרת אינדקס

המערך עצמו אינו משתנה. האינדקס i קובע איזה חלק של המערך נשאר לטיפול והזימון הראשון קובע מאיזה תא מתחילים.

// סכום הערכים בתאים מהאינדקס i עד סוף המערך
public static int SumFrom(int[] a, int i)
{
    if (i == a.Length) return 0;
    return a[i] + SumFrom(a, i + 1);
}

הזימון הראשון כאן הוא SumFrom(a, 0). פעולה שיורדת מסוף המערך מזומנת עם a.Length - 1 ונעצרת כאשר i == -1. פעולה שמקבלת שני אינדקסים נעצרת כשהם שווים או כשהשמאלי עובר את הימני.

איך עוקבים אחרי רקורסיה בלי להתבלבל

המעקב נרשם כעץ של קריאות. החיצים בעץ מראים מי זימן את מי ואיזה ערך חזר.

  1. לכל זימון מסרטטים מסגרת וכותבים בראשה את שם הפעולה עם ערכי הפרמטרים של הזימון הזה.
  2. בתוך המסגרת רושמים את השורות שמתבצעות ואת התוצאה של כל בדיקה (✓ או ✗). מתחילים בתנאי העצירה.
  3. בשורה שיש בה קריאה רקורסיבית עוצרים, מסרטטים מסגרת חדשה מתחת ומחברים אליה חץ. המסגרת הקודמת עדיין לא הסתיימה והיא מחכה לערך.
  4. כשמסגרת מגיעה ל־return, כותבים את הערך המוחזר על חץ שעולה חזרה ורושמים אותו ליד השורה שחיכתה לו. אחר כך ממשיכים במסגרת שזימנה אותה.
  5. הערך שמוחזר מהמסגרת הראשונה הוא התשובה.
  • כשיש שתי קריאות באותה מסגרת, מסיימים את כל הענף של הקריאה הראשונה לפני שמתחילים את השנייה.
  • ברקורסיה על עץ בינארי אפשר לרשום את המעקב על סרטוט העץ עצמו: כותבים ליד כל צומת את הערך שמוחזר מהקריאה על הצומת הזה, מהעלים אל השורש.
  • כשהפעולה משנה את המבנה (שרשרת, תור), מסרטטים אותו מחדש אחרי כל שינוי. בשאלות כאלה מבקשים להציג את המבנה בסיום הפעולה.
  • שימו לב שתנאי מורכב לא תמיד מחושב עד סופו. בביטוי A && B, כאשר A שקר, B אינו מחושב. בביטוי A || B, כאשר A אמת, B אינו מחושב. כאשר B הוא קריאה רקורסיבית שלא חושבה, לא מסרטטים לה מסגרת במעקב.
  • כשפעולה מחזירה ערך לפני סוף הקלט (לדוגמה: return true ברגע שנמצא איבר מתאים), היא לא קוראת לעצמה שוב ולכן לא מסרטטים מסגרות נוספות.

קריאה אחת בכל מסגרת: CountEven (תבנית 1) על השרשרת 4 → 7 → null

סיבוכיות זמן הריצה של פעולה רקורסיבית

זמן הריצה = מספר הקריאות × העבודה שנעשית בכל קריאה. סופרים קודם כמה קריאות יהיו ואחר כך בודקים מה נעשה בכל קריאה חוץ מהקריאה הרקורסיבית עצמה: מספר קבוע של צעדים, לולאה או זימון של פעולה אחרת.

איך מנסחים תשובה על סיבוכיות

  1. מגדירים את n: "נסמן ב־n את מספר החוליות בשרשרת". כשיש שני מבנים, כל אחד מקבל אות משלו: n ו־m.
  2. כותבים כמה קריאות מתבצעות ומה נעשה בכל אחת.
  3. כותבים את התוצאה. אם היא תלויה גם במבנה הקלט ולא רק בגודלו, מציינים שמדובר במקרה הגרוע.

בעץ, המקרה הגרוע לפעולה שיורדת במסלול אחד הוא עץ שבו לכל צומת בן יחיד, כי אז המסלול עובר בכל n הצמתים.

אותה קריאה פעמיים

כשאותה קריאה רקורסיבית כתובה בקוד פעמיים, היא מתבצעת פעמיים יחד עם כל הקריאות שהיא פותחת. זה קורה שוב בכל אחת מהקריאות האלה ולכן הסיבוכיות יכולה לעלות מ־O(n) ל־O(2ⁿ).

if (Height(t.GetLeft()) > Height(t.GetRight()))
    return Height(t.GetLeft()) + 1;   // אותה קריאה

כשכותבים פעולה, שומרים את התוצאה במשתנה ומשתמשים בו. כשמנתחים קוד נתון, בודקים אם אותה קריאה מופיעה בו פעמיים.

מה חוזר בשאלות הרקורסיה בבגרות

שאלות הרקורסיה בבגרות דומות זו לזו כמעט תמיד. אלה הדברים שחוזרים בהן:

  • הקוד נתון. בשאלה אופיינית לא מבקשים לכתוב פעולה רקורסיבית, אלא לעקוב אחרי פעולה נתונה ולהסביר מה היא עושה. שמות הפעולות אינם רומזים על תפקידן (What, Foo, Sod1, Secret). בשאלות על עץ בינארי, לעומת זאת, מבקשים בדרך כלל לכתוב פעולה וכותבים אותה ברקורסיה.
  • יש שתי פעולות והשנייה מזמנת את הראשונה. סעיף א עוסק בפעולה הראשונה. בסעיף ב נכתב לעיתים קרובות שאין צורך לעקוב אחרי הפעולה הראשונה.
  • יש שני סוגים של פעולות. בחלק מהשאלות החישוב העיקרי נעשה אחרי שהקריאה הרקורסיבית חזרה (תבניות 1, 4 ו־5). בשאלות אחרות הפעולה היא בדיקה שמחזירה תשובה ברגע שהיא ידועה (תבנית 2).
  • סוג הקלט משתנה משאלה לשאלה. הקלט יכול להיות עץ בינארי, שרשרת חוליות, תור, מערך או מספר שעוברים על ספרותיו.

מה עושים כשנכתב "אין צורך לעקוב"

בסעיף א כבר הבנתם מה הפעולה הראשונה עושה. בסעיף ב, בכל מקום שבו היא מזומנת, רושמים מיד את התוצאה שלה לפי מה שהבנתם ולא עוקבים אחריה שוב.

לדוגמה: נניח שבסעיף א מצאתם ש־What(lst, x) מוחקת מהשרשרת את כל החוליות שערכן x. הפעולה Guess עוברת על השרשרת. לכל חוליה היא מזמנת את What על החוליות שאחריה, עם הערך של החוליה הזאת. לכן Guess מוחקת ערכים כפולים ומשאירה מכל ערך את המופע הראשון.

הסיבוכיות של הפעולה השנייה

כששואלים על סיבוכיות, הפעולה השנייה מזמנת בדרך כלל את הראשונה בכל קריאה והראשונה עוברת על כל המבנה. במקרה כזה מכפילים: יש n קריאות ובכל אחת מהן עבודה של עד n.

בדוגמה של What ו־Guess שבתיבה הסמוכה: הסיבוכיות של What היא O(n) כי היא מבצעת קריאה אחת לכל חוליה. Guess מזמנת את What פעם אחת לכל חוליה ולכן הסיבוכיות שלה היא O(n²).

יש שאלות על תור שבהן מספר האיברים בתור אינו משתנה ורק פרמטר מספרי קטן מקריאה לקריאה. נניח שהפרמטר מתחיל במספר האיברים n וקטן ב־1 בכל קריאה. אם בכל קריאה פעולת עזר סורקת את כל התור, יש עד n קריאות שבכל אחת מהן עבודה של n והתוצאה היא O(n²) במקרה הגרוע. כשפעולה משווה כל צומת של עץ שבו n צמתים לכל הצמתים של עץ שבו m צמתים, התוצאה היא O(n·m).

"מה עושה הפעולה?"

התשובה היא משפט אחד שנכון לכל קלט ולא תיאור של שורות הקוד. כך עונים גם כששואלים "מהי מטרת הפעולה?".

  • תשובה לא טובה: "הפעולה בודקת אם הגענו לסוף השרשרת ואם לא, היא קוראת לעצמה...".
  • תשובה טובה: "הפעולה מחזירה את מספר החוליות שערכן זוגי".
  • בפעולה שמחזירה אמת או שקר כותבים מתי מוחזר true. לדוגמה: "הפעולה מחזירה true כאשר x נמצא במערך, אחרת false".

כדי להגיע למשפט הזה שואלים: מה כל איבר מוסיף לתוצאה? איך מחברים את מה שחזר מהקריאות (סכום, מקסימום, "וגם", "או")? אם המעקב שנדרש בשאלה לא מספיק כדי להבין, עוקבים אחרי הפעולה על קלט קטן נוסף ובודקים שהמשפט מתאים גם לו.

כשבשאלה נכתבה הנחה על הקלט (לדוגמה: "התור ממוין בסדר עולה"), המשפט מתאר מה הפעולה עושה כשהקלט מקיים את ההנחה.

סעיפים של חשיבה הפוכה

יש סעיפים שבהם נותנים את התוצאה ומבקשים את הקלט:

  • "הבא דוגמה למספר בעל 3 ספרות שעבורו זימון הפעולה יחזיר ערך שונה" (שונה מהערך שהתקבל במעקב).
  • "כתבו זימון נוסף שעבורו יוחזר הערך 50".
  • "בעבור עץ שיש לו 6 צמתים, מהו המספר הכי גבוה שהפעולה יכולה להחזיר? הציגו את העץ".

מתחילים מהמשפט שכתבתם בתשובה ל"מה עושה הפעולה". לפיו מחליטים אילו איברים מגדילים את התוצאה ואילו מקטינים אותה ובונים קלט קטן. בסוף עוקבים אחרי הפעולה עם הקלט שבניתם ומוודאים שמתקבל הערך המבוקש. יש שאלות שבהן מבקשים להראות את המעקב הזה בתשובה.

מה צריך לבדוק בקוד הנתון לפני שמתחילים לעקוב

  • איזה פרמטר מתקרב לתנאי העצירה. זה לא תמיד מבנה הנתונים. יש שאלות שבהן התור נשאר שלם ורק המספר n קטן. בשאלות אחרות המערך אינו משתנה והאינדקס i יורד מהתא האחרון.
  • מהו תנאי העצירה שכתוב בקוד. פעולה על עץ יכולה להיעצר בעלה ולא בעץ ריק. שתי פעולות באותה שאלה יכולות להיעצר במקומות שונים: אחת כאשר i == -1 והשנייה כאשר i == 0.
  • האם הפעולה יכולה להחזיר תשובה לפני סוף הקלט. כשזה קורה במעקב, לא מסרטטים מסגרות נוספות מתחת לקריאה שהחזירה את התשובה.
  • האם הפעולה משנה את המבנה. יש שאלות שבהן כל קריאה מעבירה איבר מראש התור לסופו ושואלים איך נראה התור בסיום. כשהפעולה מוחקת חוליות, מבקשים להציג את השרשרת אחרי המחיקה.

בפעולה שמעבירה איברים מראש התור לסופו ייתכן שישאלו מה יקרה אם תנאי העצירה יוחלף ב־q.IsEmpty(). התור אינו מתרוקן, כי כל קריאה מוציאה איבר ומכניסה אותו בחזרה. לכן הפעולה קוראת לעצמה בלי סוף והתוכנית נעצרת בשגיאת זמן ריצה.

טעויות נפוצות

כל שורה כאן מתארת טעות שתלמידים עושים ולא הנחיה.

בכתיבה

  • שוכחים return לפני הקריאה הרקורסיבית ולכן הערך שחזר הולך לאיבוד.
  • פונים ל־p.GetValue() או ל־t.GetLeft() לפני שבודקים ש־p או t אינו null. במערך פונים ל־a[i] לפני שבודקים שהאינדקס i בתחום.
  • קוראים לפעולה על אותו קלט בלי להקטין אותו ולכן הרקורסיה לא נעצרת.
  • מחזירים ערך לא מתאים בתנאי העצירה. הערך המתאים הוא 0 לסכום ולספירה, 1 למכפלה, true לבדיקה אם כל האיברים מתאימים ו־false לבדיקה אם קיים איבר מתאים.
  • בפעולה שמחזירה חוליה (תבנית 5) שוכחים את SetNext ולכן השינוי לא נשמר בשרשרת.

במעקב

  • מחשבים את הערך המוחזר בדרך למטה, לפני שהקריאה שמתחת חזרה.
  • מתבלבלים בין מה שמתבצע לפני הקריאה ובין מה שמתבצע אחריה (תבנית 3).
  • ממשיכים לרשום קריאות אחרי שהפעולה כבר החזירה תשובה באמצע הקלט.
  • מניחים שתנאי העצירה הוא התנאי המקובל (קלט ריק) בלי לקרוא את התנאי שכתוב בקוד.
  • שוכחים שפרמטר מטיפוס int מועתק בכל קריאה. שינוי שלו בקריאה אחת אינו משפיע על הקריאה שזימנה אותה. לעומת זאת שרשרת, עץ ותור משותפים לכל הקריאות ושינוי בהם נשאר.
  • עוקבים שוב אחרי הפעולה הראשונה בסעיף שבו נכתב שאין צורך בכך ומבזבזים זמן.
