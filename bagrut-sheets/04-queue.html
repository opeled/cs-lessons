מהו תור ואילו פעולות יש לו

בתור, האיבר שנכנס ראשון הוא האיבר שיוצא ראשון. איבר חדש נכנס תמיד לסוף התור. האיבר שיוצא הוא תמיד האיבר שבראש התור.

הפעולהמה היא עושה
new Queue<int>()יוצרת תור ריק של מספרים שלמים
q.Insert(x)מכניסה את x לסוף התור
q.Remove()מוציאה את האיבר שבראש התור ומחזירה אותו
q.Head()מחזירה את האיבר שבראש התור בלי להוציא אותו
q.IsEmpty()מחזירה true כשאין בתור איברים
  • לתור אין אינדקסים. אין לו גם פעולה שמחזירה את מספר האיברים, אלא אם נתונה בשאלה פעולה כזאת.
  • אפשר לראות רק את האיבר שבראש התור. כדי להגיע לאיבר אחר מוציאים את כל האיברים שלפניו. לכן אי אפשר לסרוק תור בלי להוציא ממנו איברים.
  • זימון של Remove או של Head על תור ריק גורם לשגיאת זמן ריצה. לפני כל זימון כזה בודקים שהתור אינו ריק.
  • משתנה מטיפוס תור מכיל הפניה לתור. פעולה שמקבלת תור ומוציאה ממנו איברים משנה את התור המקורי, כלומר את התור שהועבר אליה בזימון. ההשמה Queue<int> t = q; אינה יוצרת תור נוסף: t ו־q מפנים לאותו תור.

שלוש דרכים לסרוק תור ולהשאיר אותו כפי שהיה

בשלוש הדרכים כל איבר יוצא מהתור פעם אחת, נבדק וחוזר לתור. ההבדל ביניהן הוא איך יודעים שהסריקה הסתיימה.

1. תור עזר

מעבירים את כל האיברים לתור עזר ובסוף מחזירים אותם לתור המקורי. הסדר נשמר, כי גם תור העזר מוציא את האיברים בסדר שבו הם נכנסו אליו.

public static int Count(Queue<int> q, int x)
{
    Queue<int> temp = new Queue<int>();
    int count = 0;
    while (!q.IsEmpty())
    {
        int v = q.Remove();
        if (v == x) count++;
        temp.Insert(v);
    }
    while (!temp.IsEmpty())
        q.Insert(temp.Remove());
    return count;
}

הדרך הזאת מתאימה לכל שאלה: לא צריך לדעת את מספר האיברים ולא צריך ערך מיוחד שמסמן את סוף הסריקה.

2. סמן בסוף התור

מכניסים לסוף התור סמן, כלומר ערך שאינו יכול להופיע בתור. כל איבר שנבדק חוזר לסוף התור. כשהסמן מגיע לראש התור, כל האיברים כבר נבדקו.

q.Insert(-1);            // הסמן
while (q.Head() != -1)
{
    int v = q.Remove();
    if (v == x) count++;
    q.Insert(v);
}
q.Remove();              // מוציאים את הסמן

בוחרים את הסמן לפי מה שנתון בשאלה על הערכים בתור. בקוד שלמעלה הסמן הוא -1, כי ההנחה היא שאין בתור מספרים שליליים. כשכל המספרים בתור גדולים מ־0, הסמן יכול להיות גם 0.

3. מספר האיברים ידוע

כשמספר האיברים n ידוע, מעבירים איבר מראש התור לסופו n פעמים. אחרי n העברות התור חוזר לסדר המקורי.

for (int i = 0; i < n; i++)
{
    int v = q.Remove();
    if (v == x) count++;
    q.Insert(v);
}

האם צריך לשמור על התור

כשכתוב "חובה לשמור על מבנה התור"

  • בסיום הפעולה התור מכיל את אותם איברים באותו סדר, גם כשהפעולה מחזירה false.
  • לא כותבים return בתוך הסריקה. שומרים את התשובה במשתנה ומחזירים אותה אחרי שכל האיברים חזרו לתור.
  • דרך נוספת: יוצרים העתק של התור (ראו "העתקה של תור") ומוציאים איברים רק מההעתק.

כשכתוב "אין צורך לשמור על התור"

  • סורקים בלולאה while (!q.IsEmpty()) ומוציאים איברים בלי להחזיר אותם. מותר גם לכתוב return באמצע הסריקה.
  • בסיום הפעולה התור ריק או שחסרים בו איברים. זימון נוסף של הפעולה על אותו תור עלול להחזיר תשובה אחרת.

פעולות שכדאי להכיר

העתקה של תור

כל איבר שיוצא מהתור נכנס גם להעתק וגם לתור עזר.

public static Queue<int> Copy(Queue<int> q)
{
    Queue<int> copy = new Queue<int>();
    Queue<int> temp = new Queue<int>();
    while (!q.IsEmpty())
    {
        int v = q.Remove();
        copy.Insert(v);
        temp.Insert(v);
    }
    while (!temp.IsEmpty())
        q.Insert(temp.Remove());
    return copy;
}

השוואה בין שני תורים

שני תורים זהים כשיש בהם אותם ערכים באותו סדר. משווים בין העתקים של שני התורים. לכן התורים המקוריים נשמרים גם כשהפעולה מחזירה false באמצע הלולאה.

public static bool Same(Queue<int> q1,
                        Queue<int> q2)
{
    Queue<int> a = Copy(q1);
    Queue<int> b = Copy(q2);
    while (!a.IsEmpty() && !b.IsEmpty())
        if (a.Remove() != b.Remove())
            return false;
    return a.IsEmpty() && b.IsEmpty();
}

אם באחד ההעתקים נשארו איברים, מספר האיברים בשני התורים שונה והפעולה מחזירה false.

הכנסה לתור ממוין בסדר עולה

מעבירים לתור עזר את האיברים שקטנים מ־x או שווים לו, מכניסים את x לתור העזר, מעבירים אליו את שאר האיברים ובסוף מחזירים את כל האיברים לתור המקורי.

public static void InsertSorted(Queue<int> q,
                                int x)
{
    Queue<int> temp = new Queue<int>();
    while (!q.IsEmpty() && q.Head() <= x)
        temp.Insert(q.Remove());
    temp.Insert(x);
    while (!q.IsEmpty())
        temp.Insert(q.Remove());
    while (!temp.IsEmpty())
        q.Insert(temp.Remove());
}

הוצאה של איברים מסוימים

מעבירים לתור עזר רק את האיברים שצריכים להישאר ובסוף מחזירים אותם לתור המקורי.

public static void RemoveAll(Queue<int> q,
                             int x)
{
    Queue<int> temp = new Queue<int>();
    while (!q.IsEmpty())
    {
        int v = q.Remove();
        if (v != x) temp.Insert(v);
    }
    while (!temp.IsEmpty())
        q.Insert(temp.Remove());
}

טיפול בקבוצות של איברים שווים

מוציאים את האיבר הראשון. סורקים את שאר התור. איבר ששווה לאיבר הראשון שייך לקבוצה שלו ולכן אינו חוזר לתור. אם השאלה דורשת, סופרים אותו או מוסיפים אותו לסכום של הקבוצה. איבר אחר עובר לתור עזר ובסוף הסריקה חוזר לתור. חוזרים על כל התהליך עד שהתור ריק.

// הפעולה מחזירה כמה ערכים שונים יש בתור. בסיום הפעולה התור ריק
public static int CountDifferent(Queue<int> q)
{
    Queue<int> temp = new Queue<int>();
    int count = 0;
    while (!q.IsEmpty())
    {
        int first = q.Remove();
        count++;
        while (!q.IsEmpty())
        {
            int v = q.Remove();
            if (v != first) temp.Insert(v);
        }
        while (!temp.IsEmpty())
            q.Insert(temp.Remove());
    }
    return count;
}

תור של עצמים

האיבר ש־Remove ו־Head מחזירות הוא עצם. ניגשים לתכונות שלו רק בעזרת הפעולות Get ו־Set של המחלקה. בדוגמה, למחלקה Student יש הפעולה GetGrade שמחזירה את הציון של התלמיד.

public static int CountPassed(Queue<Student> q)
{
    int count = 0;
    while (!q.IsEmpty())
    {
        Student s = q.Remove();
        if (s.GetGrade() >= 55) count++;
    }
    return count;
}
  • הביטוי q.Head().GetGrade() מחזיר את הציון של העצם שבראש התור בלי להוציא אותו מהתור.
  • כשהפעולה צריכה להחזיר תור חדש (res) שבו עצמים חדשים, יוצרים כל עצם בעזרת הפעולה הבונה ומכניסים אותו לתור החדש: res.Insert(new Student(name, g));
  • התור שומר הפניות לעצמים. לכן שינוי של עצם בעזרת Set נראה גם בתור, אבל המקום של העצם בתור נשאר כפי שהיה.
  • בתור של עצמים הסמן (דרך 2) יכול להיות null.

מעקב אחרי קוד שמשתמש בתור

  1. לפני שמתחילים, מוצאים בסרטוט את הכיתוב "ראש התור". כותבים את התור בטבלת המעקב באותו כיוון שבו הוא מסורטט בשאלה.
  2. בכל סיבוב של הלולאה רושמים שורה חדשה: תוכן התור, ערכי המשתנים וערכי התנאים.
  3. Remove מוציאה את האיבר שבראש התור (במעקב מוחקים אותו מהשורה). Insert מכניסה איבר לסוף התור. Head אינה משנה את התור.
  4. בהוראה q.Insert(q.Remove()); האיבר שבראש התור עובר לסופו. מספר האיברים אינו משתנה.
  5. בסיום רושמים את הערך המוחזר וגם את מצב התור, כי לעיתים שואלים איך נראה התור בסיום הפעולה.
q.Insert(-1);
int max = -1;
while (q.Head() != -1)
{
    int v = q.Remove();
    if (v > max) max = v;
    q.Insert(v);
}
q.Remove();

זהו מעקב אחרי הקוד שמימין למטה. בתור יש מספרים חיוביים. ראש התור בצד שמאל והתור ההתחלתי הוא 4, 9, 2.

אחרי סיבוב 3 הסמן נמצא בראש התור ולכן הלולאה מסתיימת. ההוראה האחרונה מוציאה את הסמן והתור חוזר למצבו ההתחלתי.

בפעולה רקורסיבית שמקבלת תור, כל הקריאות עובדות על אותו תור. שינוי שקריאה אחת עשתה בתור נשאר גם בקריאות שאחריה. לכן רושמים את מצב התור בכל קריאה.

סיבוכיות זמן ריצה של פעולות על תור

איך מנסחים תשובה על סיבוכיות

  1. מגדירים את n: "נסמן ב־n את מספר האיברים בתור".
  2. כותבים כמה פעמים מתבצעת הלולאה החיצונית וכמה צעדים מתבצעים בכל סיבוב שלה, כולל פעולות עזר שמזומנות בתוכה.
  3. כשהתשובה תלויה בתוכן התור, מתארים את המקרה הגרוע. לדוגמה: בפעולה שמטפלת בקבוצות של איברים שווים כותבים "במקרה הגרוע כל הערכים שונים. בסריקה הראשונה עוברים על n-1 איברים, בשנייה על n-2 וכן הלאה ולכן הסיבוכיות היא O(n²)".

פעולת עזר בתוך תנאי הלולאה

for (int i = 0; i < Size(q); i++)   // לא כך

int n = Size(q);                    // כך
for (int i = 0; i < n; i++)

התנאי של הלולאה נבדק מחדש בכל סיבוב. כשהפעולה Size סופרת את האיברים בסריקה של התור, הסיבוכיות של הלולאה הראשונה היא O(n²) גם אם הגוף שלה קצר. בנוסף, אם גוף הלולאה מוציא איברים, מספר האיברים משתנה במהלך הלולאה. לכן שומרים את מספר האיברים במשתנה לפני הלולאה.

מה חוזר בשאלות על תור בבגרות

  • שאלות כתיבה ושאלות מעקב. יש שאלות שבהן כותבים פעולה ויש שאלות שבהן עוקבים אחרי קוד נתון או אחרי אלגוריתם שמתואר במילים.
  • סעיף ב שנשען על סעיף א. לעיתים קרובות נכתב בסעיף ב שמותר או שחובה להשתמש בפעולה מסעיף א. גם מי שלא הצליח בסעיף א יכול לזמן את הפעולה בסעיף ב לפי הכותרת שלה.
  • ההערות שמתחת לשאלה. ההערות קובעות מה מותר בפתרון. בשאלת כתיבה נכתב בדרך כלל אם צריך לשמור על התור. יש שאלות שבהן נאסר להשתמש במערך או בשרשרת חוליות ונכתב שפתרון כזה לא יזוכה בנקודות. בשאלות האלה משתמשים רק בתורי עזר ובמשתנים רגילים.
  • תור של עצמים. האיברים בתור יכולים להיות עצמים של מחלקה שמוגדרת בשאלה (לדוגמה: הזמנה, קובייה, חולה, נבדק).
  • סיבוכיות. יש שאלות שבהן צריך לכתוב את הסיבוכיות של כל סעיף ולנמק אותה.

ההערה על שמירת התור משתנה מסעיף לסעיף

יש שאלות שבהן נכתב בסעיף א "חובה לשמור על מבנה התור" ובסעיף ב "אין צורך לשמור". קוראים את ההערה של כל סעיף בנפרד. בסעיף שבו אין צורך לשמור כותבים את הפתרון הקצר שמוציא איברים בלי להחזיר אותם.

בודקים את ראש התור לפני שמוציאים איבר

לדוגמה: בשאלה אחת מעבירים קוביות מראש התור לקופסה. לקופסה יש פעולת הכנסה שמחזירה false כשהקובייה אינה מתאימה לקופסה. לפי השאלה, קובייה כזאת צריכה להישאר בראש התור. לכן מעבירים לפעולת ההכנסה את q.Head() ומזמנים את Remove רק אחרי שההכנסה הצליחה. מי שמוציא לפני הבדיקה מאבד את הקובייה או משנה את הסדר כשהוא מחזיר אותה לסוף התור.

מקום בתור ואיברים שכנים

יש שאלות שבהן נדרש לבדוק איבר לפי המקום שלו או לפי השכנים שלו. לדוגמה: בודקים את האיבר במקום ה־k ואת שני שכניו, משווים את M האיברים האחרונים של תור אחד ל־M הראשונים של תור אחר או מחפשים רצף של איברים שווים.

  • שומרים במשתנה את המקום של האיבר ומגדילים אותו ב־1 בכל הוצאה.
  • שומרים במשתנה את האיבר הקודם. את האיבר הבא מקבלים בעזרת Head, אחרי שבודקים שהתור אינו ריק.
  • לאיבר הראשון ולאיבר האחרון יש רק שכן אחד ולכן מטפלים בהם בנפרד.
  • כדי להגיע ל־M האיברים האחרונים סופרים קודם את האיברים (n) ואז מעבירים לסוף התור את n-M הראשונים.

קבוצות של עצמים עם אותו מזהה (לדוגמה: שם לקוח)

בשאלה אחת נדרש לאחד הזמנות של אותו לקוח ובשאלה אחרת נדרש למצוא את העיר שבה מספר החולים הגדול ביותר. בשאלות כאלה האיברים אינם ממוינים, מותר לשנות את התור והפתרון בנוי כמו הפעולה שבסעיף "טיפול בקבוצות של איברים שווים".

  • כשנכתב שהמזהה (לדוגמה: קוד העיר) אינו קשור למספר האיברים בתור, המזהה יכול להיות גדול ממספר האיברים ולא ידוע מה הערך הגדול ביותר שלו. לכן אי אפשר להשתמש בו כאינדקס במערך מונים.
  • כשסעיף ב מחלק את הקבוצות לפי סכום (לדוגמה: לקוחות לפי סך כל המוצרים שלהם), מאחדים קודם את ההזמנות של כל לקוח (זו הפעולה שנכתבה בסעיף א) ורק אחר כך בודקים את הסכום. שימו לב לערך הגבול של התנאי: כשהתנאי הוא "10 ומעלה", גם לקוח שהזמין 10 מוצרים עומד בתנאי.
  • כשבתור המוחזר צריכה להופיע קודם קבוצה אחת ואחריה קבוצה שנייה, ממלאים שני תורים ובסוף מעבירים את איברי התור השני לסוף התור הראשון.

הכנסה לתור ממוין: מה קורה כשיש שוויון

לדוגמה: התור ממוין לפי רמת דחיפות בסדר יורד וחולה חדש נכנס אחרי החולים שכבר ממתינים באותה רמה. לכן מעבירים לתור העזר את כל מי שהדחיפות שלו גדולה מזו של החדש או שווה לה. אם משמיטים מהתנאי את השוויון, החולה החדש נכנס לפני החולים שממתינים באותה רמה.

כשהדחיפות של חולה שכבר נמצא בתור משתנה, שינוי התכונה בעזרת Set אינו מזיז את החולה בתור. מוציאים את החולה מהתור, מעדכנים את הדחיפות שלו ומכניסים אותו מחדש בעזרת פעולת ההכנסה לתור ממוין.

כשבשאלה נתונה פעולת Size

כשבשאלה נתונה פעולה שמחזירה את מספר האיברים, זה רמז לסריקה בדרך 3. לדוגמה: כדי לבדוק אם יש בתור שני איברים שסכומם x, מוציאים איבר ובודקים את הסכום שלו עם כל אחד מהאיברים שנשארו. את האיברים שנשארו סורקים בהעברה מראש התור לסופו.

בשאלה אחרת נדרש לבדוק אם תור אחד מתקבל מהשני בהעברות מראש התור לסופו. מעבירים איבר מראש התור לסופו לכל היותר n פעמים ואחרי כל העברה בודקים אם שני התורים זהים. בלי ההגבלה ל־n העברות הלולאה אינה מסתיימת כשהתורים שונים.

מעקב אחרי פעולה עם סמן ואחרי פעולה שמזמנת אותה

לדוגמה: נתונה פעולה Mmm שמכניסה 0 לסוף תור של מספרים חיוביים וסורקת את התור עד שה־0 מגיע לראש התור (דרך 2). בטבלת המעקב רושמים בכל סיבוב את תוכן התור, את ערכי המשתנים ואת ערכי התנאים.

  • הלולאה ממשיכה עד שהסמן מגיע לראש התור, גם אחרי שהתשובה כבר ידועה. כך התור חוזר למצבו ההתחלתי. מאותה סיבה הסיבוכיות היא O(n) בכל מקרה.
  • לפני המעקב מבררים מה הפעולה בודקת. לדוגמה: Mmm מקבלת גם מספר z ובודקת אם יש בתור רצף של z איברים שווים וסמוכים. אין לבלבל בין האורך של רצף כזה לבין מספר הפעמים שערך מופיע בתור כולו.
  • יש שאלות שבהן פעולה רקורסיבית What מזמנת את Mmm בכל קריאה. בקריאה הראשונה z שווה למספר האיברים בתור (n) ובכל קריאה נוספת z קטן ב־1. התור עצמו אינו משתנה בין הקריאות. הרקורסיה נעצרת כש־Mmm מחזירה true ולכל המאוחר כש־z מגיע ל־1, כי איבר אחד הוא רצף של איבר אחד. לכן יש עד n קריאות שכל אחת מהן סורקת n איברים: O(n²) במקרה הגרוע.

רקורסיה שמעבירה את ראש התור לסופו

יש שאלות שבהן כל קריאה מוציאה את האיבר שבראש התור ומכניסה אותו לסוף התור. במעקב מציגים את התור אחרי כל קריאה, את הערך המוחזר ואת מצב התור בסיום. התור בפעולה כזאת אינו מתרוקן. לכן אם תנאי העצירה הוא q.IsEmpty(), הרקורסיה אינה נעצרת והתוכנית מסתיימת בשגיאת זמן ריצה.

יש שאלות שבהן כל איבר בתור הוא ספרה של מספר וראש התור הוא ספרת האחדות. כדי לחשב את המספר מכפילים את הספרה הראשונה שיוצאת ב־1, את השנייה ב־10, את השלישית ב־100 וכן הלאה. החישוב num * 10 + d אינו מתאים כאן, כי הוא בונה את המספר עם הספרות בסדר הפוך.

בסרטוטים שבשאלות הבגרות ראש התור מסורטט בדרך כלל בצד שמאל, הפוך מכיוון הקריאה בעברית. לכן בודקים את הכיתוב "ראש התור" בכל שאלה מחדש.

טעויות נפוצות

כל שורה כאן מתארת טעות שתלמידים עושים ולא הנחיה.

בכתיבה

  • כותבים return false באמצע הסריקה בסעיף שבו חובה לשמור על התור. חלק מהאיברים נשארים בתור העזר והתור המקורי אינו חוזר למצבו.
  • מזמנים Head או Remove בלי לבדוק שהתור אינו ריק. טעות דומה: כותבים את הבדיקה !q.IsEmpty() אחרי הזימון של Head ולא לפניו, לדוגמה q.Head() <= x && !q.IsEmpty().
  • כותבים while (!q.IsEmpty()) ובגוף הלולאה מחזירים כל איבר לאותו תור. התור אינו מתרוקן והלולאה אינה מסתיימת. בסריקה כזאת משתמשים בסמן או במספר האיברים.
  • כותבים Queue<int> copy = q; ומניחים שנוצר העתק. שני המשתנים מפנים לאותו תור.
  • שוכחים להוציא את הסמן בסיום הסריקה או בוחרים סמן שיכול להופיע בתור.
  • מאתחלים מקסימום ב־0 גם כשייתכנו בתור ערכים שליליים, במקום לאתחל אותו באיבר הראשון.
  • ניגשים לתכונה של עצם בלי פעולת Get או יוצרים עצם חדש בלי להעביר ערכים לפעולה הבונה.

במעקב ובסיבוכיות

  • קוראים את התור בכיוון ההפוך ומתחילים מהאיבר שבסוף התור.
  • מתייחסים ל־Head כאילו הוציאה את האיבר או שוכחים ש־Remove מוציאה אותו.
  • בפעולה עם סמן עוצרים את המעקב כשהתשובה ידועה ולא ממשיכים עד שהסמן מגיע לראש התור.
  • בפעולה רקורסיבית מניחים שהתור קטן בכל קריאה, גם כשהקוד מחזיר כל איבר לתור.
  • מחשבים את הסיבוכיות רק לפי הלולאה שרואים בפעולה ושוכחים שפעולת העזר שמזומנת בתוכה סורקת את התור בעצמה.
  • כותבים O(n²) בלי להגדיר את n ובלי לתאר את המקרה הגרוע.
