מבנה העץ והמינוח

בעץ הזה משתמשים בדוגמאות שבהמשך הדף. יש בו 7 צמתים ו־3 מהם עלים. הגובה שלו 3. בן יחיד שהקו אליו נוטה שמאלה הוא בן שמאלי (1 הוא הבן השמאלי של 7). בן יחיד שהקו אליו נוטה ימינה הוא בן ימני (8 הוא הבן הימני של 2).

  • עץ בינארי: לכל צומת יש לכל היותר שני בנים, בן שמאלי ובן ימני. עץ ריק הוא null.
  • שורש: הצומת העליון. זהו הצומת היחיד שאין לו הורה.
  • הורה, בן ואח: הצומת 9 הוא ההורה של 4 ושל 7. הצומת 4 הוא הבן השמאלי שלו והצומת 7 הוא הבן הימני שלו. הצמתים 4 ו־7 הם אחים.
  • עלה: צומת שאין לו בנים.
  • תת־עץ: צומת יחד עם כל הצמתים שמתחתיו. תת־העץ השמאלי של 5 הוא העץ ששורשו 9 ויש בו 4 צמתים.
  • מסלול: רצף של צמתים שכל אחד מהם, חוץ מהראשון, הוא בן של הקודם לו. לדוגמה: 5, 9, 7, 1 הוא מסלול מהשורש לעלה.
  • רמה של צומת: מספר הקשתות (הקווים שמחברים הורה לבן) במסלול מהשורש אליו. השורש נמצא ברמה 0.
  • גובה העץ: מספר הקשתות במסלול הארוך ביותר מהשורש לעלה. הגובה של עץ בן צומת אחד הוא 0.

סריקות של עץ

סריקה עוברת על כל צומתי העץ, כל צומת פעם אחת. בשלוש הסריקות הרקורסיביות תת־העץ השמאלי נסרק תמיד לפני הימני. ההבדל ביניהן הוא רק המקום שבו מטפלים בשורש: לפני שתי הקריאות הרקורסיביות, ביניהן או אחריהן.

public static void Scan(BinNode<int> t)
{

הטיפול בשורש הוא בדרך כלל הדפסה. לדוגמה: Console.Write(t.GetValue() + " ");

כשסורקים ביד, מסיימים תת־עץ שלם לפני שעוברים לתת־העץ הבא. בסדר תוכי כותבים את 5 רק אחרי שכל ארבעת הצמתים שמשמאלו נכתבו.

סריקה לפי רמות אינה רקורסיבית. היא משתמשת בתור של צמתים שעדיין לא טופלו.

public static void PrintLevels(BinNode<int> t)
{
    if (t == null) return;
    Queue<BinNode<int>> q =
        new Queue<BinNode<int>>();
    q.Insert(t);
    while (!q.IsEmpty())
    {
        BinNode<int> cur = q.Remove();
        Console.Write(cur.GetValue() + " ");
        if (cur.GetLeft() != null)
            q.Insert(cur.GetLeft());
        if (cur.GetRight() != null)
            q.Insert(cur.GetRight());
    }
}

צומת שנכנס לתור ראשון יוצא ממנו ראשון. לכן כל הצמתים של רמה אחת יוצאים מהתור לפני הצמתים של הרמה שמתחתיה. מכניסים לתור רק בנים שקיימים. אם מכניסים null, הזימון cur.GetValue() גורם לשגיאת ריצה.

איך כותבים פעולה רקורסיבית על עץ

חושבים רק על השורש של העץ שהפעולה קיבלה ועונים על שלוש השאלות מדף הרקורסיה:

  1. מה מחזירים עבור עץ ריק? זהו תנאי העצירה t == null. בוחרים ערך שאינו משפיע על החישוב בצומת שמעליו. לדוגמה: 0 בסכום.
  2. מה מקבלים משתי הקריאות? קוראים לפעולה פעם אחת על תת־העץ השמאלי ופעם אחת על הימני. מניחים ששתיהן מחזירות תשובה נכונה.
  3. מה עושים עם השורש ועם שתי התוצאות? לחישוב הזה קוראים בדף "השילוב". פעולות שונות נבדלות זו מזו בעיקר בשילוב.
public static int F(BinNode<int> t)
{
    if (t == null)
        return 0;
    int left = F(t.GetLeft());
    int right = F(t.GetRight());
    return 1 + left + right;
}

השלד הזה סופר את הצמתים. כדי לקבל פעולה אחרת מחליפים את הערך שמוחזר עבור עץ ריק ואת שורת השילוב לפי הטבלה. בפעולה שמחזירה אמת או שקר מחליפים גם את int ב־bool. בטבלה cond הוא התנאי שבודקים בשורש. הקוד המלא של "האם קיים" ושל גובה העץ נמצא בדף הרקורסיה (תבניות 2 ו־4).

כמה תוצאות באותה סריקה. כשצריך לספור שני דברים או יותר באותה סריקה, יוצרים מערך של מונים פעם אחת לפני הזימון ומעבירים אותו כפרמטר. המערך משותף לכל הקריאות ולכן כולן מעדכנות את אותם מונים. הפעולה הרקורסיבית אינה מחזירה ערך.

קודם יוצרים את המערך: int[] c = new int[2]; ואחר כך מזמנים את Count(t, c). בסיום c[0] הוא מספר הערכים הזוגיים ו־c[1] הוא מספר האי־זוגיים. הדוגמה מניחה שאין בעץ ערכים שליליים, כי השארית של מספר שלילי אי־זוגי היא -1 ואין במערך תא כזה.

public static void Count(BinNode<int> t, int[] c)
{
    if (t == null) return;
    c[t.GetValue() % 2]++;
    Count(t.GetLeft(), c);
    Count(t.GetRight(), c);
}

שמונה דוגמאות לפעולות רקורסיביות על עץ

דוגמה 1. ספירת עלים: מקרה נפרד לעלה

בודקים אם הצומת הוא עלה מיד אחרי שבודקים אם העץ ריק.

public static int Leaves(BinNode<int> t)
{
    if (t == null) return 0;
    if (t.GetLeft() == null &&
        t.GetRight() == null)
        return 1;
    return Leaves(t.GetLeft())
         + Leaves(t.GetRight());
}

דוגמה 2. מקסימום: אין ערך מתאים לעץ ריק

מניחים שהעץ שהפעולה מקבלת אינו ריק וקוראים לה רק על בנים שקיימים.

public static int Max(BinNode<int> t)
{
    int max = t.GetValue();
    if (t.GetLeft() != null)
        max = Math.Max(max, Max(t.GetLeft()));
    if (t.GetRight() != null)
        max = Math.Max(max, Max(t.GetRight()));
    return max;
}

דוגמה 3. השוואה של כל צומת לבנים שלו

הפעולה Bigger בודקת אם כל צומת גדול מהבנים שלו. בודקים כל בן רק אם הוא קיים.

public static bool Bigger(BinNode<int> t)
{
    if (t == null) return true;
    BinNode<int> l = t.GetLeft();
    BinNode<int> r = t.GetRight();
    if (l != null && l.GetValue() >= t.GetValue())
        return false;
    if (r != null && r.GetValue() >= t.GetValue())
        return false;
    return Bigger(l) && Bigger(r);
}

דוגמה 4. פרמטר שעובר מההורה לבנים: מספר הצמתים ברמה k

הפרמטר k אומר כמה רמות עוד צריך לרדת. בכל ירידה לבן מקטינים אותו ב־1.

public static int AtLevel(BinNode<int> t, int k)
{
    if (t == null) return 0;
    if (k == 0) return 1;
    return AtLevel(t.GetLeft(), k - 1)
         + AtLevel(t.GetRight(), k - 1);
}

באותה דרך מעבירים לבנים את הערך של ההורה או את הסכום שנצבר עד כה.

דוגמה 5. מסלול מהשורש לעלה

הפעולה Path בודקת אם יש מסלול מהשורש לעלה שסכום ערכיו sum. מעבירים לבנים את הסכום שעוד חסר ובודקים אם הוא 0 רק כשמגיעים לעלה.

public static bool Path(BinNode<int> t, int sum)
{
    if (t == null) return false;
    sum = sum - t.GetValue();
    if (t.GetLeft() == null &&
        t.GetRight() == null)
        return sum == 0;
    return Path(t.GetLeft(), sum)
        || Path(t.GetRight(), sum);
}

דוגמה 6. יורדים בשני עצים יחד

הפעולה Same בודקת אם שני העצים זהים בצורה ובערכים. מטפלים קודם במקרים שבהם לפחות אחד מהעצים ריק.

public static bool Same(BinNode<int> a,
                        BinNode<int> b)
{
    if (a == null && b == null) return true;
    if (a == null || b == null) return false;
    return a.GetValue() == b.GetValue()
        && Same(a.GetLeft(), b.GetLeft())
        && Same(a.GetRight(), b.GetRight());
}

דוגמה 7. בניית עץ חדש

הפעולה מחזירה את השורש של העץ שבנתה. לדוגמה: העתק של עץ.

public static BinNode<int> Copy(BinNode<int> t)
{
    if (t == null) return null;
    return new BinNode<int>(Copy(t.GetLeft()),
        t.GetValue(), Copy(t.GetRight()));
}

דוגמה 8. שינוי של עץ קיים

הפעולה אינה מחזירה ערך. לדוגמה: הכפלת כל הערכים ב־2.

public static void Twice(BinNode<int> t)
{
    if (t == null) return;
    t.SetValue(t.GetValue() * 2);
    Twice(t.GetLeft());
    Twice(t.GetRight());
}

צומת חדש מוסיפים כך: t.SetLeft(new BinNode<int>(x))

מעקב אחרי פעולה רקורסיבית על הסרטוט של העץ

  1. מעתיקים את העץ למחברת. צמתים שיש להם אותו ערך מסמנים באותיות שונות כדי להבדיל ביניהם.
  2. מתחילים בעלים. ליד כל עלה רושמים את הערך שהפעולה מחזירה עבורו. אם הפעולה נקראת גם על בן חסר, רושמים במקומו את הערך שהיא מחזירה עבור null.
  3. ממשיכים מהעלים כלפי מעלה. צומת מקבל ערך רק אחרי ששני הבנים שלו קיבלו ערך.
  4. הערך שנרשם ליד השורש הוא התשובה.

הקריאות נפתחות מהשורש כלפי מטה, אבל הערכים חוזרים מהעלים כלפי מעלה. הערכים חוזרים בסדר של הסריקה הסופית (postorder). לפי הסדר הזה ממלאים את טבלת המעקב.

פעולה שמחזירה אמת או שקר: ב־A && B, כש־A החזירה שקר, הקריאה B אינה מתבצעת. ב־A || B, כש־A החזירה אמת, הקריאה B אינה מתבצעת. במעקב מציינים אילו תתי־עצים לא נסרקו.

פעולה שמזמנת פעולת עזר בכל צומת: כשכתוב בשאלה שאין צורך לעקוב אחרי פעולת העזר, רושמים ליד כל צומת רק את הערך שהיא מחזירה עבור תת־העץ שלו.

בדוגמה עוקבים אחרי הפעולה Height, שמחזירה את גובה העץ. עבור עץ ריק היא מחזירה -1. הקווים המקווקווים מסמנים את הבנים החסרים של 7 ושל 2. גם עבור כל בן חסר של עלה הפעולה מחזירה -1.

סיבוכיות זמן הריצה של פעולות על עץ

מסמנים ב־n את מספר הצמתים בעץ. הכלל מדף הרקורסיה נכון גם כאן: הסיבוכיות היא מספר הקריאות כפול העבודה שנעשית בכל קריאה. בעץ בן n צמתים יש n קריאות על צמתים ועוד n+1 קריאות על בנים חסרים, כלומר מספר הקריאות הוא O(n).

מה הפעולה עושהסיבוכיות
מבקרת בכל צומת פעם אחת ועושה בו מספר קבוע של צעדים. כך גם סריקה לפי רמות בעזרת תורO(n)
מזמנת בכל צומת פעולת עזר שסורקת את תת־העץ של אותו צומתO(n²) במקרה הגרוע
מזמנת בכל צומת של עץ אחד פעולת עזר שסורקת עץ אחר בן m צמתיםO(n·m)
יורדת במסלול אחד מהשורש, קריאה אחת בכל רמהלפי גובה העץ. במקרה הגרוע O(n)

דוגמה עם שני עצים: הפעולה Shared מחזירה כמה מהערכים של t1 נמצאים גם ב־t2. עבור כל צומת של t1 היא מזמנת את Exists, פעולה שבודקת אם ערך נמצא בעץ (הקוד שלה בדף הרקורסיה). כל זימון כזה סורק את t2.

public static int Shared(BinNode<int> t1,
                         BinNode<int> t2)
{
    if (t1 == null) return 0;
    int c = 0;
    if (Exists(t2, t1.GetValue()))
        c = 1;
    return c + Shared(t1.GetLeft(), t2)
             + Shared(t1.GetRight(), t2);
}

התשובה O(n+m) שגויה כאן, כי הסריקה של t2 חוזרת עבור כל צומת של t1. כשנתון ששני העצים באותו גודל כותבים O(n²).

צורת העץ במקרה הגרוע: עץ שבו לכל צומת חוץ מהעלה יש בן יחיד. הגובה שלו הוא n-1 והגדלים של תתי־העצים הם n, n-1, n-2 וכן הלאה עד 1. פעולת עזר שסורקת כל אחד מהם עושה בסך הכול כ־n²/2 צעדים.

עצירה מוקדמת בגלל && או || חוסכת חלק מהקריאות הרקורסיביות אך אינה משנה את הסיבוכיות במקרה הגרוע.

איך מנסחים את התשובה לפעולה Shared

"נסמן ב־n את מספר הצמתים ב־t1 וב־m את מספר הצמתים ב־t2. הפעולה מבקרת פעם אחת בכל צומת של t1. בכל ביקור היא מזמנת את Exists, שסורקת במקרה הגרוע את כל t2 בזמן O(m). לכן סיבוכיות זמן הריצה היא O(n·m)."

מה חוזר בשאלות העצים בבגרות

  • הפעולה שכותבים בשאלת עצים קצרה בדרך כלל. הקושי הוא בבחירת הערך לעץ ריק ובטיפול בצומת שיש לו בן אחד.
  • יש שאלות שבהן הקוד נתון. מבקשים בהן לעקוב אחרי הפעולה ולהסביר במילים מה היא עושה. יש בהן גם סעיפי חשיבה הפוכה, שמוסברים בהמשך הדף. בשאלות אחרות נדרשים סרטוט של עץ וכתיבת פעולה.
  • יש שאלות שמגדירות סוג חדש של עץ ומביאות דוגמאות לעצים מהסוג הזה. שמות של סוגים כאלה: "עץ מספרים", "עץ טווחים מסודר", "עץ שאריות שוויוני", "עץ K־שמאלי". קוראים את ההגדרה מילה במילה ובודקים מה כל דוגמה מוסיפה. יש שאלות שבהן רק אחת מהדוגמאות מראה פרט שאינו ברור מההגדרה.

מסלול מהשורש לעלה

בשאלות האלה יורדים בעץ ומעבירים לכל בן מידע על המסלול מהשורש עד אליו (דוגמה 5 בדף). לדוגמה:

  • האם יש מסלול מהשורש לעלה שערכיו עולים. משווים כל צומת לבן שאליו יורדים.
  • מדפיסים לכל מסלול את המספר שהספרות שלו הן ערכי הצמתים במסלול. הפרמטר num הוא המספר שנצבר עד הצומת. בכל צומת מחשבים num * 10 + t.GetValue().
  • האם יש מסלול מהשורש שהתווים שבצמתים שלו יוצרים מחרוזת נתונה. הפרמטר הוא החלק של המחרוזת שעוד לא נבדק.
  • האם בכל מסלול יש לכל היותר K קשתות שמאליות. קשת שמאלית היא ירידה לבן שמאלי. הפרמטר הוא מספר הקשתות השמאליות שעוד מותרות. מקטינים את הפרמטר רק בירידה שמאלה.

כשדי במסלול אחד שמקיים את התנאי, מחזירים false עבור עץ ריק ומחברים ב־||. כשהתנאי חל על כל המסלולים, מחזירים true עבור עץ ריק ומחברים ב־&&.

פעולה שמזמנת פעולת עזר בכל צומת

פעולת העזר מחשבת משהו על עץ שלם. הפעולה הראשית עוברת על העץ ומזמנת את פעולת העזר על תת־העץ של כל צומת.

  • בשאלת מעקב כתוב בדרך כלל שאין צורך לעקוב אחרי פעולת העזר (ראו בפרק המעקב).
  • פעולת העזר יכולה להחזיר 0 עבור העץ כולו וערך אחר עבור תת־עץ. לדוגמה: פעולת העזר מחזירה את מספר הצמתים בתת־העץ השמאלי פחות מספרם בימני. הפעולה הראשית בודקת שהתוצאה היא 0 בכל צומת. כשלשורש שני בנים ולכל אחד מהם רק בן שמאלי, מתקבל 0 עבור השורש (2 פחות 2) אבל 1 עבור כל בן. לכן הפעולה הראשית מחזירה false.
  • יש שאלות כתיבה שבהן פעולת העזר סורקת עץ שני ומבקשים גם את הסיבוכיות, שהיא O(n·m).

סעיפי חשיבה הפוכה: מסרטטים עץ או כותבים זימון

סעיפים אופייניים:

  • מציאת הערך הגדול ביותר והערך הקטן ביותר שהפעולה מחזירה עבור עץ בן 6 צמתים.
  • הצגת עץ בן יותר מ־3 צמתים שעבורו הפעולה מחזירה תוצאה הפוכה מזו שהתקבלה במעקב.
  • כתיבת זימון שמחזיר ערך שונה מזה שהתקבל במעקב או זימון שמחזיר ערך נתון, כמו 50.
  • סרטוט עץ מהסוג החדש לפי דרישות הסעיף. לדוגמה: "עץ 1־שמאלי" בן 8 צמתים שיש בו לכל היותר 4 רמות.

מתחילים מהמשפט שמתאר מה הפעולה עושה ושואלים איזה סוג צומת מגדיל את התוצאה ואיזה מקטין אותה. לדוגמה: בפעולה שבה צומת שיש לו רק בן ימני מוסיף 1 ועלה אינו מוסיף דבר, הערך הגדול ביותר לעץ בן 6 צמתים הוא 5 ולא 6, כי בכל עץ יש לפחות עלה אחד. העץ שנותן את הערך הזה הוא שרשרת של בנים ימניים.

אחרי הסרטוט סופרים שוב את הצמתים ואת הרמות מול הדרישה ועוקבים אחרי הפעולה על העץ החדש.

"מה הפעולה מחזירה?": התשובה תלויה בסוג הצומת

בודקים מה הפעולה מחזירה בכל אחד מהמקרים: עץ ריק, עלה, בן שמאלי בלבד, בן ימני בלבד, שני בנים. מהמקרים האלה מרכיבים משפט אחד. לדוגמה:

  • כשהקוד אינו מזמן את GetValue, הערכים שבצמתים אינם משפיעים. תשובה אופיינית: מספר הצמתים שיש להם רק בן ימני פחות מספר הצמתים שיש להם רק בן שמאלי.
  • פעולה שמקבלת עץ ומספר x מחזירה את סכום הערכים של הצמתים שיש להם בן שערכו x. היא סוכמת את ערכי ההורים ולא את ערכי הצמתים שערכם x.
  • פעולה אחרת מחזירה 0 עבור עץ ריק ואת ערך הצומת עבור עלה. בכל צומת אחר היא מוסיפה את ערך הצומת לגדולה משתי התוצאות. התשובה היא הסכום הגדול ביותר של מסלול מהשורש לעלה. כשיש בעץ ערכים שליליים התשובה הזאת אינה מדויקת, כי ה־0 שחוזר מבן חסר משתתף בהשוואה ועשוי להיבחר.

טעויות נפוצות

כל שורה כאן מתארת טעות שתלמידים עושים ולא הנחיה.

בכתיבת פעולה

  • פונים ל־t.GetLeft().GetValue() בלי לבדוק קודם שהבן השמאלי קיים.
  • מטפלים בעץ ריק כאילו הוא עלה או שוכחים שלצומת יכול להיות בן אחד בלבד.
  • בודקים את התנאי בשורש בלבד ושוכחים לקרוא לפעולה על שני תתי־העצים.
  • מחברים ב־|| כשהתנאי צריך להתקיים בכל הצמתים או ב־&& כשדי בצומת אחד.
  • מחזירים 0 עבור עץ ריק בפעולת מקסימום כשייתכנו בעץ ערכים שליליים.
  • מחפשים ערך רק בתת־עץ אחד. העץ אינו ממוין ולכן צריך לחפש בשניהם.
  • בפעולה שמוסיפה צמתים קוראים לה גם על הצומת שנוסף זה עתה ואז היא מוסיפה צמתים גם לו.

במעקב, בהסבר ובסרטוט

  • מחשבים לפי הערכים שבצמתים גם כשהקוד אינו מזמן את GetValue.
  • מתבלבלים בין בן שמאלי יחיד ובין בן ימני יחיד. צריך לבדוק בסרטוט לאיזה צד הקו נוטה.
  • רושמים קריאות שלא התבצעו בגלל העצירה המוקדמת של && או של ||.
  • שוכחים את הקריאות על בנים חסרים. כשהפעולה מחזירה עבור עץ ריק ערך שאינו 0, הערך הזה משתתף בחישוב של ההורה.
  • מתבלבלים בין שני צמתים שיש להם אותו ערך.
  • מסרטטים עץ שאינו עומד בדרישות הסעיף, כמו מספר הצמתים או מספר הרמות.
  • בסיבוכיות שוכחים להגדיר את n או כותבים O(n) לפעולה שמזמנת בכל צומת פעולת עזר שסורקת תת־עץ.
