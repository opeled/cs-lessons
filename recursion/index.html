שאלה 1 (25 נקודות)

שליח נמצא בתחילת רחוב ובו n בניינים, הממוספרים 1 עד n. השליח עומד לפני בניין 1, בנקודת ההתחלה (מסומנת 0). בכל נסיעה הוא יכול להתקדם בניין אחד או שני בניינים קדימה. המשלוח צריך להגיע בדיוק לבניין n.

שימו לב שלשליח יש כמה דרכים שונות להגיע לבניין. למשל, אל בניין 3 יש לו 3 דרכי הגעה שונות:

דרך 10 → 1 → 2 → 3
דרך 20 → 1 → 3
דרך 30 → 2 → 3

שימו לב: דרך 2 ודרך 3 שונות זו מזו, מכיוון שהשליח עוצר בבניינים שונים.

  1. א. כתבו פעולה רקורסיבית public static int Ways(int n), המקבלת את מספר הבניין n ומחזירה את מספר דרכי ההגעה השונות שבהן השליח יכול להגיע מנקודת ההתחלה אל בניין n.
  2. ב. לשליח נוספה אפשרות: בנסיעה אחת הוא יכול להתקדם בניין אחד, שני בניינים או חמישה בניינים. כתבו פעולה רקורסיבית public static int Ways5(int n), המחזירה את מספר דרכי ההגעה השונות אל בניין n במצב החדש.
  3. ג. כתבו מה תחזיר הפעולה Ways5(4). עליכם להראות מעקב. אם ערכה של קריאה כבר חושב במעקב, מותר להשתמש בו שוב, בתנאי שתציינו זאת.
  4. ד.
    1. (1) מהו סוג הרקורסיה בפעולה Ways? נמקו.
    2. (2) מהי סיבוכיות זמן הריצה של Ways(n)? ומהי של Ways5(n)? נמקו.
סעיף א׳

שליח ברחוב

שליח של וולט נמצא בתחילת רחוב ובו n בניינים, הממוספרים 1 עד n. השליח עומד לפני בניין 1, בנקודת ההתחלה (מסומנת 0). בכל נסיעה הוא יכול להתקדם בניין אחד או שני בניינים קדימה. המשלוח צריך להגיע בדיוק לבניין n.

שימו לב שלשליח יש כמה דרכים שונות להגיע לבניין. למשל, אל בניין 3 יש לו 3 דרכי הגעה שונות:

כתבו פעולה רקורסיבית:
public static int Ways(int n)
הפעולה מקבלת את מספר הבניין n ומחזירה את מספר דרכי ההגעה השונות שבהן השליח יכול להגיע מנקודת ההתחלה אל בניין n.
פתרון

איך ניגשים לבעיה?

במקום לחשוב על כל המסלול, חושבים על הנסיעה האחרונה. השליח הגיע לבניין n בנסיעה של בניין אחד (ולפני כן היה בבניין n − 1) או בנסיעה של שני בניינים (ולפני כן היה בבניין n − 2). אם נחשב את מספר הדרכים אל הבניין הקודם ואל הבניין שלפניו ונחבר אותן, נגיע לפתרון.

לכן מספר הדרכים אל בניין n הוא:

Ways(n) = Ways(n−1) + Ways(n−2)

כדי להפוך את הרעיון לפעולה רקורסיבית, צריך לחשוב על שלושה דברים:

לחצו על כל אחד משלושת הכרטיסים כדי להוסיף את החלק שלו לקוד.

1

תנאי עצירה

מתי התשובה ידועה בלי רקורסיה? אל בניין 1 יש דרך אחת ואל בניין 2 יש שתיים (1+1 או 2). בלי שני התנאים האלה הרקורסיה תגיע ל־Ways(0) ול־Ways(−1) ולא תיעצר.

✓ נוסף לקוד
2

קריאה רקורסיבית

מה הפרמטרים של הקריאה הרקורסיבית? n − 1 ו־n − 2. זו אותה בעיה, רק קטנה יותר: הדרכים אל הבניין הקודם ואל הבניין שלפניו.

✓ נוסף לקוד
3

שילוב התוצאות

מה עושים עם מה שחזר? כאן מחברים, כי כל דרך אל n מסתיימת באחת משתי הנסיעות ונספרת פעם אחת בלבד.

✓ נוסף לקוד
public static int Ways(int n)
{
    // 1. תנאי עצירה    if (n == 1)
        return 1;        // דרך אחת: נסיעה של 1
    if (n == 2)
        return 2;        // שתי דרכים: 1+1 או 2

    // 2. קריאה רקורסיבית    int p1 = Ways(n - 1);  // השליח הגיע מבניין n−1
    int p2 = Ways(n - 2);  // השליח הגיע מבניין n−2
    // 3. שילוב התוצאות    return p1 + p2;
}
סעיף ב׳

הרחבה: גם נסיעה של 5

לשליח נוספה אפשרות: בנסיעה אחת הוא יכול להתקדם בניין אחד, שני בניינים או חמישה בניינים.

כתבו פעולה רקורסיבית:
public static int Ways5(int n)
הפעולה מחזירה את מספר דרכי ההגעה השונות אל בניין n במצב החדש.
פתרון

מה משתנה?

את הקריאה הרקורסיבית קל להרחיב: הנסיעה האחרונה יכולה להיות גם של 5, אז מוסיפים קריאה שלישית Ways5(n − 5) ומחברים שלושה ערכים. מה שדורש מחשבה הוא תנאי העצירה.

לחצו על כל אחד מהכרטיסים כדי להוסיף את החלק שלו לקוד.

1

תנאי עצירה

למה n == 1 ו־n == 2 כבר לא מספיקים? כי Ways5(3) קוראת ל־Ways5(−2) ושום תנאי לא עוצר אותה. היה אפשר לכתוב תנאי נפרד לכל אחד מ־Ways5(1) עד Ways5(5), אבל עדיף תנאי שמתאים לכל n: אם n == 0 הגענו ליעד וזו דרך אחת. אם n < 0 עברנו את היעד ואין דרך. בדיקה: Ways5(1) = Ways5(0) + Ways5(−1) + Ways5(−4) = 1.

✓ נוסף לקוד
2

קריאה רקורסיבית

מה הפרמטרים עכשיו? n − 1, n − 2 ו־n − 5, לפי הבניין שממנו הגיע השליח בנסיעה האחרונה.

✓ נוסף לקוד
3

שילוב התוצאות

מה עושים עם מה שחזר? כמו קודם מחברים: כל דרך אל n מסתיימת באחת משלוש הנסיעות ונספרת פעם אחת.

✓ נוסף לקוד
public static int Ways5(int n)
{
    // 1. תנאי עצירה    if (n == 0)
        return 1;        // הגענו ליעד: דרך אחת
    if (n < 0)
        return 0;        // עברנו את היעד: אין דרך

    // 2. קריאה רקורסיבית    int p1 = Ways5(n - 1);
    int p2 = Ways5(n - 2);
    int p3 = Ways5(n - 5);
    // 3. שילוב התוצאות    return p1 + p2 + p3;
}

תנאי העצירה האלה היו עובדים גם ב־Ways מסעיף א׳. הם מתאימים לכל n ולכן בדרך כלל כדאי להתחיל מהם.

סעיף ד׳

סוג הרקורסיה וסיבוכיות

לחצו על שאלה כדי לראות את התשובה.

  1. מהו סוג הרקורסיה בפעולה Ways? נמקו.
  2. מהי סיבוכיות זמן הריצה של Ways(n)? ומהי של Ways5(n)? נמקו.
  3. בונוס בעץ הקריאות הקריאה Ways5(2) מופיעה פעמיים. הסבירו מדוע זה קורה ומה זה אומר על גודל העץ כאשר n גדל.
תשובות
1. סוג הרקורסיה: הלוך־חזור.
אחרי שהקריאה הרקורסיבית חוזרת עוד יש מה לעשות: צריך לחבר את הערכים שחזרו (p1 + p2). לכן זו אינה רקורסיית זנב, שבה הקריאה הרקורסיבית היא הפעולה האחרונה והערך שלה מוחזר כמו שהוא. זו גם אינה רקורסיה הדדית, כי יש כאן פעולה אחת שקוראת לעצמה ולא שתי פעולות שקוראות זו לזו.
2. סיבוכיות: Ways(n) היא O(2n) ו־Ways5(n) היא O(3n).
כאן הסיבוכיות היא מספר הקריאות. ב־Ways כל קריאה (שלא עצרה בתנאי העצירה) פותחת שתי קריאות חדשות וכך שוב ושוב לאורך n רמות: מכפילים ב־2 n פעמים, 2 · 2 · … · 2 = 2n. ב־Ways5 כל קריאה פותחת שלוש ולכן 3n.

למה לא n2? n2 מתאים למשל לפעולה רקורסיבית על מערך שבה יש n קריאות וכל קריאה עוברת על כל המערך: n קריאות כפול n פעולות בכל אחת. כאן כל קריאה עושה מספר קבוע של פעולות. מה שגדל הוא רק מספר הקריאות.

למה לא n? O(n) מתאים לרקורסיה שבה כל קריאה פותחת קריאה אחת, למשל מעבר על מערך מאינדקס לאינדקס: שרשרת של n קריאות. כאן כל קריאה פותחת שתיים (או שלוש) ולכן מספר הקריאות מוכפל בכל רמה: 1, 2, 4, 8, …

כך נראה העץ המלא של Ways5(4) בלי שום קיצור: קריאות בשביל התשובה 5.

3. בונוס, חישוב חוזר: גם Ways5(4) וגם Ways5(3) קוראות ל־Ways5(2). כל אחת מהן מחשבת אותה מחדש בלי ״לזכור״ שכבר חושבה. ככל ש־n גדל, אותם ערכים קטנים חוזרים ומופיעים בחלקים רבים של העץ. זה מקור הגידול המעריכי: רוב העבודה בעץ היא חזרה על חישובים שכבר נעשו. במעקב בסעיף ג׳ הרשינו לעצמנו לכתוב ״חושב כבר״ ולקצר, אבל המחשב לא מקצר. אם הפעולה הייתה שומרת כל תוצאה שחישבה, היא הייתה צריכה לחשב רק n ערכים שונים.
